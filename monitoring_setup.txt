1. АРХИТЕКТУРА СИСТЕМЫ МОНИТОРИНГА
=============================================================================

Система мониторинга состоит из трех компонентов:

┌─────────────────────────┐
│ Text Embedding Service  │
│   (FastAPI + OTel)      │
│   Port: 5000            │
│   Endpoint: /metrics    │
└────────┬────────────────┘
         │ (pull model, каждые 5 сек)
         ▼
┌─────────────────────────┐
│      Prometheus         │
│   Port: 9090            │
│   Хранение метрик       │
└────────┬────────────────┘
         │ (query)
         ▼
┌─────────────────────────┐
│        Grafana          │
│   Port: 3000            │
│   Визуализация          │
└─────────────────────────┘

Модель сбора метрик: PULL (Prometheus запрашивает метрики у сервиса)

2. ПРЕДВАРИТЕЛЬНЫЕ ТРЕБОВАНИЯ
=============================================================================

Установите следующие компоненты:

1. Docker Engine (версия 20.10+)
   $ docker --version
   
2. Docker Compose (версия 2.0+)
   $ docker compose version

3. NVIDIA Container Toolkit (для GPU поддержки)
   https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html
   
   Проверка:
   $ nvidia-smi
   $ docker run --rm --gpus all nvidia/cuda:12.2.0-base-ubuntu22.04 nvidia-smi

3. УСТАНОВКА И ЗАПУСК СЕРВИСОВ
=============================================================================

ШАГ 3.1: Клонируйте репозиторий
--------------------------------
$ git clone <repository-url>
$ cd text-embedding-service

ШАГ 3.2: Настройте переменные окружения
----------------------------------------
$ cp .env.example .env

Отредактируйте .env при необходимости:
- MODEL_NAME: имя модели (по умолчанию BAAI/bge-m3)
- DEVICE: устройство (cuda/cpu/mps)
- BATCH_SIZE: размер батча для обработки
- WORKER_THREADS: количество рабочих потоков
- TASK_TTL_MINUTES: время хранения завершенных задач

ШАГ 3.3: Запустите все сервисы
-------------------------------
$ docker compose up -d --build

Проверьте статус контейнеров:
$ docker compose ps

Ожидаемый вывод:
- text-embedding-service: running
- prometheus: running
- grafana: running

ШАГ 3.4: Проверьте доступность сервисов
----------------------------------------
Text Embedding Service:
$ curl http://localhost:5000/health
Ожидаемый ответ: {"status":"ok"}

Prometheus:
$ curl http://localhost:9090/-/healthy
Ожидаемый ответ: Prometheus Server is Healthy

Grafana:
Откройте в браузере: http://localhost:3000
Логин: admin
Пароль: admin

4. НАСТРОЙКА PROMETHEUS
=============================================================================

Prometheus автоматически настроен через docker-compose.yml.

Конфигурация находится в: monitoring/prometheus.yml

Проверка статуса targets:
1. Откройте: http://localhost:9090/targets
2. Убедитесь, что text-embedding-service имеет статус "UP"

Просмотр метрик:
1. Откройте: http://localhost:9090/graph
2. Введите запрос, например:
   - rate(http_server_duration_count[1m])
   - task_manager_tasks_active
   - model_inference_duration_seconds_sum

=============================================================================
5. НАСТРОЙКА GRAFANA
=============================================================================

Grafana автоматически настроена через provisioning:

- Datasource: Prometheus (монтируется из provisioning/datasources/)
- Dashboard: Text Embedding Service Dashboard (монтируется из dashboards/)

ШАГ 5.1: Вход в Grafana
------------------------
URL: http://localhost:3000
Логин: admin
Пароль: admin

При первом входе система предложит сменить пароль.

ШАГ 5.2: Проверка datasource
-----------------------------
1. Перейдите: Configuration → Data Sources
2. Убедитесь, что Prometheus настроен и имеет статус "Data source is working"

ШАГ 5.3: Просмотр дашборда
---------------------------
1. Перейдите: Dashboards → Browse
2. Откройте "Text Embedding Service Dashboard"

Дашборд содержит следующие панели:
- HTTP Request Rate: количество запросов в секунду
- HTTP Request Duration: время обработки запросов (p50, p95, p99)
- Active Tasks: количество активных задач (gauge)
- Service Status: статус сервиса (Up/Down)
- Model Inference Duration: время инференса модели
- Process Memory Usage: использование памяти процессом
- GPU Utilization: утилизация GPU (если доступно)
- Task Manager - Tasks by Status: задачи по статусу
- Embeddings Generated Rate: скорость генерации эмбеддингов

6. ИСПОЛЬЗОВАНИЕ ДАШБОРДА
=============================================================================

ШАГ 6.1: Базовые операции
--------------------------
- Изменение временного диапазона: используйте time picker в правом верхнем углу
- Обновление: кнопка "Refresh dashboard" или автообновление (настроено на 5 сек)
- Фильтрация: используйте переменные в верхней части дашборда

ШАГ 6.2: Мониторинг производительности
---------------------------------------
Ключевые метрики для наблюдения:

1. Latency (HTTP Request Duration):
   - p50 < 100ms для /api/embedding/
   - p95 < 500ms для /api/compare_batch/
   - p99 < 2s для любых эндпоинтов

2. Throughput (HTTP Request Rate):
   - Мониторьте падение RPS при высокой нагрузке
   - Сравните с Model Inference Duration

3. Resource Usage:
   - Process Memory: должно быть стабильным
   - GPU Utilization: оптимально 70-90% при нагрузке

4. Task Manager:
   - Active Tasks: не должно расти бесконечно
   - Tasks by Status: следите за количеством failed задач

ШАГ 6.3: Настройка алертов (опционально)
-----------------------------------------
1. Перейдите: Alerting → Alert rules
2. Создайте новое правило:
   - Name: High Error Rate
   - Condition: rate(http_server_duration_count{status="5xx"}[5m]) > 0.1
   - For: 1m
   - Notification: email/slack/pagerduty

7. ДОБАВЛЕНИЕ НОВЫХ МЕТРИК
=============================================================================

ШАГ 7.1: Добавление метрики в код
----------------------------------
1. Откройте app/metrics.py
2. Создайте новую метрику:

   from app.metrics import meter
   
   my_custom_metric = meter.create_counter(
       name='my_custom_metric_total',
       description='Описание метрики',
       unit='1'
   )

3. Используйте метрику в коде:

   from app.metrics import my_custom_metric
   
   my_custom_metric.add(1, {'label': 'value'})

ШАГ 7.2: Добавление панели в дашборд
-------------------------------------
1. Откройте Grafana
2. Перейдите на дашборд
3. Нажмите "Add panel"
4. Выберите тип визуализации (Time series, Stat, Gauge, etc.)
5. Настройте запрос:
   - Data source: Prometheus
   - Query: ваша метрика, например:
     rate(my_custom_metric_total[5m])

6. Настройте визуализацию:
   - Title: название панели
   - Unit: единица измерения
   - Thresholds: пороги для цветовой индикации

7. Сохраните дашборд

ШАГ 7.3: Экспорт обновленного дашборда
---------------------------------------
1. В Grafana: Dashboard settings → JSON Model
2. Скопируйте JSON
3. Сохраните в monitoring/grafana/dashboards/text-embedding-service.json
4. Перезапустите Grafana:
   $ docker compose restart grafana

8. TROUBLESHOOTING
=============================================================================

ПРОБЛЕМА: Сервис не запускается
--------------------------------
Проверьте логи:
$ docker compose logs text-embedding-service

Возможные причины:
- GPU недоступен: проверьте nvidia-smi и настройку NVIDIA Container Toolkit
- Модель не загружается: проверьте доступность HuggingFace или скачайте модель локально
- Порт занят: измените порт в docker-compose.yml

ПРОБЛЕМА: Prometheus не собирает метрики
-----------------------------------------
1. Проверьте targets: http://localhost:9090/targets
2. Убедитесь, что text-embedding-service имеет статус "UP"
3. Проверьте доступность /metrics:
   $ curl http://localhost:5000/metrics

ПРОБЛЕМА: Grafana не показывает данные
---------------------------------------
1. Проверьте datasource: http://localhost:3000/datasources
2. Убедитесь, что Prometheus доступен из контейнера Grafana
3. Проверьте логи Grafana:
   $ docker compose logs grafana

ПРОБЛЕМА: Метрики отсутствуют или нулевые
-----------------------------------------
1. Сделайте несколько запросов к сервису:
   $ curl -X POST http://localhost:5000/api/embedding/ \
      -H "Content-Type: application/json" \
      -d '{"text": "Hello world"}'

2. Подождите 15-30 секунд (интервал скрейпинга)
3. Проверьте метрики в Prometheus:
   http://localhost:9090/graph?g0.expr=rate(http_server_duration_count[1m])

ПРОБЛЕМА: Высокая загрузка CPU/GPU
-----------------------------------
1. Уменьшите WORKER_THREADS в .env
2. Уменьшите BATCH_SIZE
3. Ограничьте количество одновременных задач

ПРОБЛЕМА: Out of memory
------------------------
1. Увеличьте память контейнера в docker-compose.yml:
   deploy:
     resources:
       limits:
         memory: 16G

2. Уменьшите MAX_TEXTS_PER_TASK
3. Уменьшите TASK_TTL_MINUTES для более быстрой очистки

10. РЕКОМЕНДАЦИИ ПО ПРОДАКШЕНУ
=============================================================================

1. БЕЗОПАСНОСТЬ:
   - Измените пароль Grafana по умолчанию
   - Настройте HTTPS для всех сервисов
   - Используйте secrets для чувствительных данных
   - Ограничьте доступ к портам 9090 и 3000

2. МАСШТАБИРОВАНИЕ:
   - Используйте load balancer (nginx/HAProxy) перед сервисами
   - Настройте Prometheus federation для нескольких инстансов
   - Используйте remote storage для Prometheus (Thanos/Cortex)

3. НАДЕЖНОСТЬ:
   - Настройте health checks в docker-compose.yml
   - Используйте restart policies
   - Настройте backup для Prometheus data
   - Настройте алерты для критических метрик

4. МОНИТОРИНГ:
   - Добавьте logging (Loki/ELK)
   - Добавьте tracing (Jaeger/Tempo)
   - Настройте SLA/SLO метрики
   - Создайте runbook для частых инцидентов
